# Сравнение Multi-Agent и Single Prompt

## Количественное сравнение

| Метрика | Multi-Agent | Single Prompt |
|---|---:|---:|
| Количество LLM-вызовов | 6 | 1 |
| Input tokens | 21 396 | 797 |
| Output tokens | 4 957 | 2 307 |
| Всего токенов | 26 353 | 3 104 |
| End-to-end latency | 112.28 s | 46.91 s |
| Количество revision-итераций | 1 | 0 |
| Стоимость внешнего API | 0 | 0 |

## Multi-Agent

### Преимущества

- отдельные роли Strategist, Copywriter, Editor и Publisher;
- явный conditional revision-loop;
- структурированное промежуточное состояние;
- возможность независимо анализировать каждый этап;
- полная трассировка выполнения в Langfuse;
- Editor может отдельно проверять и отклонять неподтверждённые утверждения;
- проще добавлять отдельные правила контроля и deterministic validation на разных этапах.

### Недостатки

- значительно большее потребление токенов;
- более высокая end-to-end latency;
- часть контекста повторно передаётся между агентами;
- revision-loop дополнительно увеличивает объём входного контекста;
- независимые агенты всё равно могут галлюцинировать;
- Editor не гарантирует обнаружение всех ошибок.

## Single Prompt

### Преимущества

- один LLM-вызов;
- значительно меньшее потребление токенов;
- более низкая latency;
- более простая реализация;
- отсутствуют дополнительные orchestration-затраты между агентами.

### Недостатки

- нет независимого Reviewer / Editor;
- отсутствует настоящий revision-loop;
- генерация и самопроверка выполняются одной и той же моделью в рамках одного вызова;
- self-review может повторять ошибочную логику основной генерации;
- сложнее понять, на каком именно этапе появилась ошибка;
- ниже наблюдаемость процесса по сравнению с multi-agent подходом.

## Наблюдаемая проблема качества Single Prompt

Single Prompt сгенерировал неподтверждённые утверждения.

Например, в постах появились утверждения о том, что система:

- получает данные о сроках договора;
- получает данные о суммах;
- анализирует ответственность;
- обрабатывает документы в защищённой среде;
- не передаёт данные третьим сторонам;
- строго контролирует доступ к документам.

Эти свойства не были указаны во входных подтверждённых фактах.

При этом в `self_review` модель указала:

> «Нет неподтверждённых фактов»

и фактически классифицировала часть придуманных свойств как подтверждённые.

Это показывает ограниченность self-review внутри одного LLM-вызова.

Генератор и критик находятся в одном контексте и могут разделять одну и ту же ошибочную предпосылку.

## Пример blind self-agreement

В Single Prompt использовалась явная инструкция проверить:

1. неподтверждённые факты;
2. неподтверждённые цифры;
3. соответствие контент-плану;
4. соответствие целевой аудитории;
5. соответствие социальной сети;
6. наличие CTA;
7. отсутствие придуманных функций продукта.

Несмотря на это, модель не обнаружила собственные галлюцинации.

Таким образом, была зафиксирована ситуация **blind self-agreement**:

`генерация ошибки → самопроверка той же моделью → ошибочное подтверждение собственной генерации`

Это является важным ограничением Single Prompt подхода.

## Стоимость по токенам

Multi-Agent использовал:

- 21 396 input tokens;
- 4 957 output tokens;
- 26 353 total tokens.

Single Prompt использовал:

- 797 input tokens;
- 2 307 output tokens;
- 3 104 total tokens.

Таким образом, Single Prompt использовал примерно на 88% меньше токенов.

Основная причина роста input tokens в Multi-Agent — повторная передача промежуточных результатов между агентами.

Наиболее тяжёлым по входному контексту оказался повторный вызов Copywriter:

- 6 163 input tokens;
- 6 852 total tokens.

На этом этапе Copywriter получает:

- исходную задачу;
- результат Strategist;
- текущую версию текста;
- замечания Editor;
- инструкции на revision.

## Сравнение производительности

End-to-end latency:

- Multi-Agent: 112.28 s
- Single Prompt: 46.91 s

Single Prompt выполнился примерно на 58% быстрее.

Для Multi-Agent основную часть времени занимают непосредственно LLM-вызовы, а не orchestration LangGraph.

Суммарная latency LLM-вызовов в normal run составила около 96.85 s при общей end-to-end latency 112.28 s.

Следовательно, основным performance bottleneck является локальный inference модели.

Самым медленным агентом оказался Strategist.

В исследованных запусках его latency составляла примерно:

- 33.08 s в normal run;
- 47.91 s в controlled revision run.

## Важное замечание по сравнению latency

Оба сравниваемых multi-agent запуска содержали одну revision-итерацию.

Поэтому увеличение времени нельзя связывать только с controlled revision-сценарием.

Также latency локального Ollama зависит не только от количества токенов.

Например:

- normal run: 26 353 tokens, 112.28 s;
- controlled revision run: 24 883 tokens, 116.84 s.

Несмотря на меньшее количество токенов, controlled run оказался немного медленнее.

Это связано с вариативностью локального inference и возможным cold-start / загрузкой модели.

## Наблюдаемость

Multi-Agent подход значительно лучше с точки зрения observability.

В Langfuse отдельно видны:

- Strategist;
- Copywriter;
- Editor;
- повторный Copywriter;
- повторный Editor;
- Publisher.

Для каждого LLM-вызова доступны:

- model;
- latency;
- time to first token;
- input tokens;
- output tokens;
- total tokens.

Это позволяет определять bottleneck конкретного агента и анализировать путь выполнения.

В Single Prompt вся логика скрыта внутри одного большого LLM-вызова.

## Итоговый вывод

Single Prompt существенно выигрывает по простоте, latency и количеству используемых токенов.

Однако Multi-Agent архитектура даёт преимущества в управляемости, модульности и наблюдаемости.

Она позволяет:

- разделить ответственность между ролями;
- организовать независимую проверку результата;
- выполнить настоящий revision-loop;
- добавить deterministic validation;
- анализировать ошибки и производительность по отдельным этапам.

При этом Multi-Agent не гарантирует фактическую корректность.

Отдельный Editor также может пропустить неподтверждённые утверждения или ошибочно поставить `APPROVED`.

Поэтому для production-системы наиболее практичным вариантом является не просто увеличение количества агентов, а сочетание:

- multi-agent orchestration;
- строгих structured outputs;
- ограниченного и управляемого контекста;
- deterministic validation;
- traceability фактов;
- Langfuse observability.

Таким образом:

**Single Prompt — быстрее и дешевле, но менее управляем.**

**Multi-Agent — дороже и медленнее, но предоставляет больше точек контроля и лучше подходит для сложных процессов с независимой проверкой и revision-loop.**
