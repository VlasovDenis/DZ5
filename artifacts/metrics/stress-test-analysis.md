# Анализ стресс-теста

## Сценарий

Для стресс-теста использовался намеренно сложный сценарий:

- ниша: промышленное оборудование для проектов атомной энергетики;
- аудитория: инженеры, технические специалисты, специалисты по закупкам и руководители проектов;
- социальная сеть: TikTok;
- набор подтверждённых фактов был намеренно сильно ограничен.

Цель теста — проверить, будет ли multi-agent система:

- придумывать технические характеристики;
- придумывать сертификации или соответствие нормативам;
- добавлять неподтверждённые утверждения о безопасности или эффективности;
- использовать сенсационный или неподходящий clickbait;
- терять исходный B2B-контекст и специфику атомной энергетики.

## Результат выполнения

- `revision_count`: 0
- `editor_approved`: true
- `forced_publish`: false
- итоговое решение Editor: `APPROVED`
- опубликовано постов: 3

Граф завершил выполнение без дополнительного цикла ревизии:

`Strategist → Copywriter → Editor → Publisher`

## Положительные результаты

Система избежала наиболее очевидных и рискованных галлюцинаций.

В итоговых постах не появились неподтверждённые утверждения о:

- сертификациях;
- соответствии нормативным требованиям;
- классах безопасности;
- сроке службы оборудования;
- численных показателях эффективности;
- конкретных клиентах;
- экономических показателях;
- конкретных технических характеристиках.

Также модель не превратила тему атомной энергетики в сенсационный или развлекательный clickbait.

Стиль остался профессиональным и ориентированным на B2B-аудиторию.

## Потеря специфики контекста

Главным недостатком стала потеря отраслевой специфики.

Хотя исходная ниша была определена как:

> промышленное оборудование для проектов атомной энергетики

итоговые посты в основном обсуждали общие темы:

- выбор промышленного оборудования;
- подготовку технического предложения;
- техническую документацию;
- обмен инженерным опытом.

Большая часть такого контента могла бы использоваться практически для любой промышленной B2B-компании.

Таким образом, проявился компромисс между безопасностью и конкретностью:

`мало подтверждённых фактов → модель избегает конкретики → снижается риск галлюцинаций → контент становится слишком общим`

Это показывает, что при недостатке подтверждённой предметной информации система может сохранять фактическую осторожность, но одновременно терять важную специфику исходного контекста.

## Адаптация под TikTok

Сгенерированные посты были короткими, содержали hook и CTA, однако адаптация именно под TikTok оказалась ограниченной.

Система не сформировала характерные элементы video-first формата:

- сценарий короткого ролика;
- визуальную последовательность;
- hook первых 2–3 секунд;
- текст для voice-over;
- on-screen text;
- структуру кадров;
- рекомендации по визуальному сопровождению.

Поэтому TikTok был интерпретирован скорее как канал для короткого текста, а не как отдельный формат короткого видео.

## Недостатки Editor

Editor утвердил результат и не выявил:

1. потерю специфики атомной энергетики;
2. слабую адаптацию под TikTok;
3. некоторые спорные неподтверждённые утверждения.

Например, в одном из постов появилась формулировка:

> «шаги, которые помогут инженерам принимать обоснованные решения без привлечения внешних специалистов»

Такой результат не был указан среди подтверждённых фактов.

При этом Editor в своём заключении написал, что неподтверждённых обещаний результата нет.

Это показывает, что отдельный Editor повышает управляемость системы, но не гарантирует обнаружение всех фактических и контекстных проблем.

## Вывод

Стресс-тест показал, что multi-agent система достаточно хорошо справляется с очевидными галлюцинациями и избегает неподходящего clickbait даже в сложной технической B2B-тематике.

Однако были выявлены два важных класса ошибок:

1. **Context dilution** — потеря специфики исходной предметной области при недостатке подтверждённых фактов.
2. **False approval** — Editor может утвердить правдоподобный, но не полностью соответствующий исходному контексту результат.

Также была выявлена слабая адаптация под video-first формат TikTok.

Для production-версии целесообразно усилить критерии проверки Editor и добавить отдельные проверки на:

- сохранение отраслевого контекста;
- соответствие формату конкретной социальной сети;
- неподтверждённые обещания результата;
- трассируемость фактических утверждений к подтверждённым входным данным;
- достаточную предметную конкретность контента.
